# 사용법

## 하는 일

**Shift+Space를 누르면 한/영 키(`VK_HANGUL`)를 대신 눌러줍니다.** 그게 전부입니다.

한/영 키가 없는 키보드(대부분의 외산 키보드, 일부 노트북)나,
한/영 키 위치가 손에 안 맞는 경우를 위한 프로그램입니다.

## 실행

설치 방법에 따라 실행 명령이 다릅니다.

| 설치 방법 | 실행 |
|---|---|
| winget | `nshiftspace` |
| Chocolatey | `nShiftSpace-x64` (32비트 OS는 `nShiftSpace-x86`) |
| zip 직접 | exe 더블클릭 |

실행하면 **창이 뜨지 않고** 트레이(작업 표시줄 오른쪽 알림 영역)에 아이콘만 생깁니다.
'가·A' 모양의 작은 픽셀 아트 아이콘입니다.

> 트레이 아이콘이 숨겨져 있다면 작업 표시줄의 **∧(숨겨진 아이콘 표시)** 를 눌러 확인하세요.
> 항상 보이게 하려면 그 상태에서 아이콘을 작업 표시줄로 끌어다 놓으면 됩니다.

로그인할 때마다 자동 실행하려면 → **[자동 실행 설정](Autostart)**

## 트레이 메뉴

**트레이 아이콘 우클릭**(또는 좌클릭)으로 엽니다.

| 항목 | 동작 |
|---|---|
| 로그인 시 자동 실행 (체크) | 켜면 지금 실행 중인 exe 경로를 시작 프로그램(HKCU `Run`)에 등록, 끄면 삭제 → [자동 실행 설정](Autostart) |
| 키보드 LED 표시 (체크, LED판만) | 키 눌림 표시 켜기/끄기 → [키보드 LED 표시판](#키보드-led-표시판-선택) |
| 종료 | 트레이 아이콘을 지우고 끝냅니다 |

## 동작 방식

```
Shift+Space 입력  →  Windows가 가로챔 (RegisterHotKey)
                  →  한/영 키(VK_HANGUL) 합성 입력
                  →  IME가 한/영 전환
```

키보드 훅(`SetWindowsHookEx`)이 아니라 **`RegisterHotKey`** 를 씁니다.
OS가 직접 키를 가로채므로 모든 키 입력을 검사할 필요가 없어 **CPU 사용량이 사실상 0**입니다.
백신이 훅 기반 프로그램을 의심하는 문제에서도 자유롭습니다.

## 알아둘 제약

### 1. 관리자 권한 창에서는 동작하지 않습니다

작업 관리자, 승격된 PowerShell 등 **관리자 권한으로 실행된 창이 포커스를 가지면**
일반 권한으로 실행된 nShiftSpace의 단축키는 전달되지 않습니다.

Windows의 UIPI(User Interface Privilege Isolation) 보안 정책 때문이며,
원조 jwShiftSpaceKey를 포함해 같은 방식의 모든 프로그램이 동일합니다.

**해결책**: nShiftSpace를 관리자 권한으로 실행하면 됩니다.
로그인 시 자동으로 승격 실행하는 방법은 [자동 실행 설정 — 방법 C](Autostart#방법-c--작업-스케줄러--관리자-창에서도-단축키가-먹게-하려면) 참고.

### 2. 단축키는 Shift+Space 고정입니다

설정 파일도, 설정 화면도 없습니다. 5KB 남짓을 유지하기 위한 의도적인 선택입니다.

키를 자유롭게 바꾸고 싶다면 개발 예정인 **nexa-mapper**를 기다려 주세요 → [로드맵](Roadmap)

### 3. 다른 프로그램이 Shift+Space를 이미 쓰고 있다면

`RegisterHotKey`는 먼저 등록한 프로그램이 우선입니다.
다른 프로그램이 선점했다면 nShiftSpace의 단축키 등록이 실패합니다.
(일부 IME, 매크로 프로그램, 게임 오버레이 등이 원인일 수 있습니다.)

## 편의 기능

| 기능 | 설명 |
|---|---|
| 중복 실행 방지 | 뮤텍스로 차단. 두 번째 인스턴스는 즉시 종료됩니다 |
| 트레이 아이콘 복구 | explorer.exe가 재시작되어도 (`TaskbarCreated` 감지) 아이콘이 자동으로 되살아납니다 |
| 로그인 시 자동 실행 | 트레이 아이콘 우클릭 → **로그인 시 자동 실행** 체크 한 번. 자세한 내용은 [자동 실행 설정](Autostart) |
| 무설정 | 기본 상태에서는 레지스트리에 아무것도 쓰지 않습니다. "로그인 시 자동 실행"을 켠 경우에만 `Run` 값 하나를 쓰고, 끄면 지웁니다. **제거 전에 끄세요** — 그러면 exe 하나만 지우면 완전 제거 |

## 키보드 LED 표시판 (선택)

Releases에는 일반판 외에 **`nShiftSpace-led-x64.zip` / `nShiftSpace-led-x86.zip`** 이 함께 올라갑니다.
Shift+Space 기능은 같고, 추가로 **아무 키나 누르는 동안 트레이 아이콘이 초록으로 켜지고 떼면
파랑으로 돌아옵니다.** 키보드 입력이 들어가고 있는지 트레이에서 한눈에 보고 싶을 때 쓰세요.

| | 일반판 | LED판 |
|---|---|---|
| 파일 | `nShiftSpace-x64.exe` | `nShiftSpace-led-x64.exe` |
| 크기 | 5,120 바이트 (x86 5,632) | 6,144 바이트 (x86 6,656) |
| 키 입력 감시 | 없음 (Shift+Space만 OS가 전달) | Raw Input으로 눌림/뗌만 수신 |
| 훅 사용 | 없음 | 없음 — 훅이 아니라서 다른 프로그램의 키 입력을 지연시키지 않습니다 |
| 메모리 | 같음 | 같음 |

**켜고 끄기**: 트레이 아이콘 우클릭 → **키보드 LED 표시** (체크 표시가 현재 상태).
끄면 키 입력 감시 자체를 해제하므로 일반판과 똑같이 키 입력당 비용이 0이 됩니다.
설정은 저장하지 않으며 다시 실행하면 켜짐으로 시작합니다 (레지스트리·설정 파일을 쓰지 않는 원칙).
항상 꺼 두고 싶다면 일반판을 쓰세요.

- winget·Chocolatey 패키지는 **일반판만** 설치합니다. LED판은 zip으로 직접 받으세요.
- 두 판은 **동시에 실행되지 않습니다** (같은 단축키·중복 실행 방지를 공유). 하나를 종료하고 다른 것을 실행하세요.
- 여러 키를 같이 누른 경우 어느 키든 떼면 꺼집니다. 켜진 상태에서 explorer가 재시작되면 꺼짐으로 초기화됩니다.

## 리소스 사용

| 항목 | 값 |
|---|---|
| 파일 크기 | 5,120 바이트 (x86 5,632 · LED판 6,144 / 6,656) |
| 메모리 | 작업 관리자 기준 약 300KB(x64) / 160KB(x86). 초기화 후 작업 집합을 비웁니다. 실제 커밋은 약 1.4MB로 Win32 트레이 앱의 바닥값 |
| CPU | 유휴 시 0% (메시지 루프 대기) |
| 의존성 | kernel32 / user32 / shell32 (+ advapi32는 자동 실행 메뉴용) 만 사용. .NET·VC++ 재배포 패키지 불필요 |
